## Context

参见 [proposal.md](proposal.md) 的动机。本需求位于 P01-S01 的入口，当前仓库只有参考项目的目标 URL 和固定落盘目录约定，尚无可供后续实验复用的上游版本与本机环境证据。设计必须同时处理嵌套 Git 仓库、潜在本地改动、敏感配置和外部服务副作用。

行为约束见 [reference-project-baseline spec](specs/reference-project-baseline/spec.md)。

## Goals / Non-Goals

**Goals:**

- 以仓库原始文件和 Git 元数据为事实来源，形成可追溯的只读基线。
- 让检查过程可重复执行，并在目录已存在、证据冲突或条件缺失时安全停止。
- 以结构化报告分开记录已验证事实、未知项、阻塞和下一需求的用户输入。

**Non-Goals:**

- 不启动完整产品流程，也不验证需要真实凭据的业务能力。
- 不修改参考项目业务文件、依赖版本或环境样例。
- 不将参考项目技术栈确定为 P01 正式项目技术栈。
- 不执行 P01-S01-02，也不更新阶段完成状态。

## Decisions

### 1. 固定目录保留独立 Git 身份

参考项目使用 `references/p01-backblaze-ai-saas-starter-kit/`，其上游 Git 元数据保留在目录内，主仓库只把它作为本地学习材料管理，不把其源码复制进 `projects/`。

选择该方案是因为 commit SHA、远程地址、分支和工作区状态必须由上游仓库直接证明。替代方案是下载源码压缩包，但它会丢失远程和工作区证据，不利于后续受控实验。

若目录不存在，则从已确认的上游 URL 获取；若目录已存在，则先核对它是否为 Git 仓库、远程是否匹配以及是否存在本地改动。任何不匹配都只报告，不覆盖、不清理、不重置。

### 2. 以证据矩阵组织调查

先枚举仓库实际存在的 README、License、包管理清单与锁文件、运行时版本文件、环境变量样例、容器配置、数据库迁移和项目级说明，再从这些文件提取结论。报告中的重要结论同时记录证据路径；多个来源冲突时保留冲突，不自行消解。

选择证据矩阵而不是按预设技术栈逐项填写，是为了避免将项目路线中的 Next.js、FastAPI 等描述误写成当前上游 commit 的事实。

### 3. 环境变量只做元数据级盘点

变量盘点只收集变量名、用途、是否必需、是否敏感、外部账户要求和费用风险。检查命令不得输出当前 shell 或本地 `.env` 的真实值；如果本机已有 Secret，也不得读取后复制到报告。

替代方案是创建完整 `.env` 后尝试启动，但这会扩大凭据泄露和外部调用风险，也超出本需求只建立启动前基线的目标。

### 4. 验证分为“仓库事实”和“本机条件”两层

第一层通过静态读取和 Git 命令确认上游事实；第二层只检查本机命令是否存在及其版本，并判断基础安装或静态检查是否安全可行。只有确认不会修改业务文件、不会写入外部系统、不会调用付费服务时才执行检查。

包安装可能生成缓存、构建产物或锁文件变化，因此默认先做可行性判断；如需安装，必须在执行前确认其写入范围，并在执行后重新核对参考仓库 Git 状态。无法保证安全时只记录命令和缺失条件。

### 5. 单一基线报告使用明确状态标签

`progress/p01/reference_baseline.md` 按需求规定的九类信息组织，并对结论使用“已验证”“未验证”“阻塞”“待用户决定”等状态。命令只记录必要参数和结果摘要，对可能包含敏感信息的输出进行省略或脱敏。

采用单一报告便于 P01-S01-02 直接接续；原始命令输出不作为必须提交的独立产物，以避免噪声和 Secret 风险。

## Risks / Trade-offs

- [上游默认分支在执行期间继续变化] → 报告以实际检出的完整 commit SHA 为唯一版本锚点，同时记录当时默认分支。
- [参考目录已有未知内容或改动] → 在任何获取、安装或检查前先核对目录和 Git 状态；不做破坏性恢复，转为阻塞报告。
- [文档、样例和实际配置不一致] → 记录每项结论的来源并显式保留冲突，避免用推断掩盖缺口。
- [命令输出意外包含 Secret] → 不读取本地变量值，命令与报告均采用允许列表式字段提取，只记录变量名和分类。
- [安装或检查改变参考仓库状态] → 执行前评估写入范围，前后对比 Git 状态；发现非预期变化立即停止并报告，不自动清理。
- [网络或外部账户不可用导致信息不完整] → 将可由本地仓库确认的基线与外部阻塞分开记录，不把未验证能力标为可运行。

## Migration Plan

1. 在任何写入前检查固定目录及主仓库状态。
2. 获取或核对参考仓库，立即记录远程、默认分支、完整 commit SHA、License 和初始 Git 状态。
3. 按证据矩阵完成结构、启动方式、环境变量、外部服务和本机运行时盘点。
4. 仅执行满足安全边界的基础检查，并再次记录参考仓库 Git 状态。
5. 生成基线报告，逐项核对规格场景；关键身份信息缺失时保留受阻状态。

本需求不部署、不迁移线上数据。若执行中断，保留已获取的参考目录和报告草稿；重试时从目录身份和 Git 状态核对重新开始，不覆盖现有内容。
