## Purpose

定义参考项目在进入运行实验前必须具备的可追溯版本、环境依赖、安全边界和基线报告，使后续 Agent 能复现同一上游状态并区分事实、缺失条件与待决事项。

## ADDED Requirements

### Requirement: 参考仓库身份必须可追溯
基线 SHALL 将 Backblaze AI SaaS Starter Kit 定位到 `references/p01-backblaze-ai-saas-starter-kit/`，并记录仓库 URL、远程地址、默认分支、实际 commit SHA 和 License。记录的 commit SHA MUST 来自参考仓库实际 Git 状态，而不是路线文档或分支名称推断。

#### Scenario: 固定上游版本
- **WHEN** 参考仓库已放入固定目录并完成身份核对
- **THEN** 基线报告包含足以让后续 Agent 获取同一上游版本的仓库 URL、默认分支和完整 commit SHA
- **THEN** 基线报告记录 License 的名称及其仓库内证据位置

#### Scenario: 固定目录中已有内容
- **WHEN** 固定目录已存在但来源、版本或工作区状态与预期不一致
- **THEN** 执行过程 MUST 保留现有内容且不得覆盖、清理或重置
- **THEN** 基线报告或执行结果明确记录差异并将其标为阻塞

### Requirement: 初始工作区状态必须保持可核验
基线 SHALL 记录参考仓库检查前后的 Git 状态，并 MUST 保持参考项目无业务逻辑改动。任何已有改动或本需求产生的非预期改动都必须被明确披露。

#### Scenario: 干净参考仓库
- **WHEN** 参考仓库在基线检查前后均无本地改动
- **THEN** 基线报告记录对应的 Git 状态为干净

#### Scenario: 检测到本地改动
- **WHEN** 参考仓库存在已修改、未跟踪或未提交文件
- **THEN** 执行过程不得擅自删除、覆盖、提交或隐藏这些改动
- **THEN** 执行结果列出状态并说明该状态是否阻止建立可信基线

### Requirement: 项目结构与启动关系必须基于仓库证据
基线 SHALL 阅读根 README、License、环境变量样例、容器配置、数据库迁移和项目级开发说明中实际存在的文件，并据此记录主要模块、包管理方式、前后端运行方式、数据库与基础设施的启动关系。不存在或无法确认的信息 MUST 标记为缺失或未知，不得用项目路线文档补写成仓库事实。

#### Scenario: 配置来源可用
- **WHEN** 仓库文件声明了运行时版本、依赖版本、启动命令或服务关系
- **THEN** 基线报告记录结论及其配置来源路径

#### Scenario: 信息无法由仓库确认
- **WHEN** 所需版本、命令或服务关系没有直接仓库证据或存在冲突
- **THEN** 基线报告将其标记为未知或冲突并列出相关证据
- **THEN** 执行过程不得静默选择一种解释作为确定事实

### Requirement: 环境变量与外部服务必须安全分类
基线 SHALL 枚举仓库声明的环境变量，并至少说明变量用途、必需或可选、敏感或非敏感，以及是否需要外部账户或可能产生费用。报告 MUST 只记录变量名、用途和条件，不得包含真实 Secret、Token、密码或私钥值。

#### Scenario: 发现敏感配置变量
- **WHEN** 环境变量用于认证、支付、对象存储、模型服务、数据库或其他敏感连接
- **THEN** 基线报告将其标记为敏感并仅记录变量名、用途和获取条件
- **THEN** 任何读取结果和报告中均不出现真实值

#### Scenario: 发现外部或付费依赖
- **WHEN** 运行能力依赖第三方账户、付费资源或可能产生费用的调用
- **THEN** 基线报告明确标记账户要求、费用风险和受影响能力
- **THEN** 本需求不得注册服务、购买资源或发起会产生外部写入或费用的操作

### Requirement: 本机运行条件必须如实评估
基线 SHALL 记录参考项目所需运行时及本机可用版本，并区分已满足、缺失、冲突和未经验证的条件。仅允许执行不会修改参考项目业务文件、不会产生外部系统写入且不会触发付费调用的基础检查。

#### Scenario: 可安全执行基础检查
- **WHEN** 某个版本、命令或静态检查可以在不写入外部系统且不暴露 Secret 的前提下验证
- **THEN** 执行结果记录所用命令、退出结果和对运行条件的结论

#### Scenario: 检查需要凭据或外部副作用
- **WHEN** 某项验证需要真实凭据、创建账户、部署、写入外部服务或可能产生费用
- **THEN** 本需求停止于可行性判断，不执行该验证
- **THEN** 基线报告将所缺条件和需要用户决定的事项列为阻塞或后续输入

### Requirement: 基线报告必须支持后续需求接续
系统 SHALL 在 `progress/p01/reference_baseline.md` 形成独立且可读的基线报告，至少覆盖来源与版本、License、目录和模块、启动组件与命令、环境变量分类、外部服务要求、当前运行条件、初始 Git 状态，以及 P01-S01-02 需要用户提供或决定的事项。

#### Scenario: 基线建立完成
- **WHEN** 所有可安全核实的项目事实已记录且未解决条件已显式标记
- **THEN** 任意后续 Agent 能从报告定位同一上游 commit 并复述主要启动关系
- **THEN** 报告明确区分已验证事实、未验证项、阻塞和用户待决事项

#### Scenario: 关键身份信息无法确认
- **WHEN** 仓库 URL、commit SHA、License 或初始工作区状态中任一关键项无法可靠确认
- **THEN** 本需求 MUST 保持未完成或受阻状态
- **THEN** 不得宣称已具备进入 P01-S01-02 的可信基线
