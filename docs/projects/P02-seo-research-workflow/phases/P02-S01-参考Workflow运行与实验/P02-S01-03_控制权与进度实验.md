# P02-S01-03：控制权与进度实验

## 1. 核心结论

通过最小代码修改观察“阶段顺序由谁控制、阶段内部内容由谁生成”，并核对前端进度是否反映真实执行。实验用于建立控制权证据，不把参考项目重构成自己的架构。

## 2. 状态

| 属性 | 内容 |
|---|---|
| 状态 | 未开始 |
| 必需前置 | P02-S01-02 已完成或关键流程已明确受阻 |
| 主要交付物 | `progress/p02/control_experiments.md` 与未提交实验差异 |

## 3. 实验范围

至少选择两项：

- 为 Planner、Search、Writer 边界增加安全日志，记录阶段顺序和数据规模；
- 修改 Planner 的查询数量上限，观察 Search 和 Writer 的连锁变化；
- 让一个 Search 请求返回空结果或失败，观察是否仍进入 Writer；
- 修改一个阶段进度事件，核对 UI 是否只是展示事件而非真实任务状态；
- 为阶段输入输出添加解释性注释或最小 Schema 校验；
- 调整 Writer 输入，验证引用来源与报告之间的依赖。

## 4. 必须回答

| 问题 | 证据来源 |
|---|---|
| 下一阶段由普通代码还是模型决定 | 调用链和实验结果 |
| Planner 输出是否结构化且受约束 | 实际响应和解析代码 |
| Search 失败是否阻止 Writer | 失败实验 |
| Progress 是否对应真实后端阶段 | 事件与日志时间线 |
| Writer 能否访问未搜索到的信息 | 实际输入边界 |

## 5. 边界

- 不引入新的 Agent 框架；
- 不大规模重构 Pipeline；
- 不升级依赖；
- 不提交、推送或部署实验改动；
- 不要求输出模型隐藏思维链，只记录可观察输入、输出和简短决策摘要。

## 6. 验收标准

- 至少两项实验可重复并有前后对比；
- 控制权表建立在代码和运行证据上；
- 进度显示与真实执行的差异被明确记录；
- 差异中没有 Secret、无关格式化或生成物；
- 对 Java Workflow 的可借鉴结论与上游专属实现已区分。

保留实验改动，不自动还原或提交。完成后报告实验记录、测试结果、`git diff --stat`、关键差异和 Git 状态，然后停止。
