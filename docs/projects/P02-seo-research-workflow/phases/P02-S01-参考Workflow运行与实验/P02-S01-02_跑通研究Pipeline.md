# P02-S01-02：跑通研究 Pipeline

## 1. 核心结论

使用一个固定研究主题实际运行 Planner → Search → Writer，记录每阶段输入、输出、耗时、进度和失败表现。无法获得全部外部条件时，允许分段验证，但必须清楚标记未形成端到端证据的部分。

## 2. 状态

| 属性 | 内容 |
|---|---|
| 状态 | 未开始 |
| 必需前置 | P02-S01-01 已完成 |
| 主要交付物 | `progress/p02/upstream_pipeline_report.md` |

## 3. 实现范围

- 按上游方式安装并启动项目；
- 选择一个稳定、非敏感的研究主题作为基线输入；
- 观察 Planner 输出的实际格式和查询数量；
- 观察 Search 使用的 API、来源数据和网页内容；
- 观察 Writer 收到的上下文、报告和引用；
- 记录前端阶段进度、Streaming 和最终状态；
- 测量总耗时、主要步骤耗时、模型与搜索调用次数；
- 主动验证至少一个可安全触发的失败场景。

## 4. 边界

- 只允许本地配置适配，不修改业务逻辑；
- 不用伪造 Search 成功来宣称端到端跑通；
- 不抓取需要登录、付费或明确禁止自动访问的内容；
- 不记录完整密钥、认证头或包含隐私的原始输入；
- 不把模型输出当作事实正确性证据。

## 5. 验收标准

- 每个阶段都有真实状态：成功、失败、受阻或未触发；
- 至少一条研究流程可以重复，或分段流程的缺口明确；
- 报告引用与搜索来源之间的实际关联已检查；
- 进度与后端真实执行阶段是否一致已有记录；
- 调用次数、耗时和主要失败行为可观察。

## 6. Coding Agent 执行要求

只执行运行与观察。涉及付费调用时先说明预计范围并等待用户决定。完成后报告运行结果、测试、临时配置和 Git 状态，不进入实验需求。
