# P02：技术栈设计

## 1. 当前结论

P02 使用 React + TypeScript 和 Java + Spring Boot。Workflow 由普通 Java 服务显式编排，不依赖自由 Agent 框架。Spring AI、LangChain4j 或直接模型 API 的选择，必须通过 P02-S03-02 的小型实验决定。

## 2. 当前选型

| 领域 | 当前选择 | 状态 |
|---|---|---|
| 前端 | React + TypeScript，优先 Vite | 方向已确认 |
| 后端 | Java + Spring Boot | 已确认 |
| 编排 | 显式 Java Workflow | 已确认 |
| AI 集成 | Spring AI / LangChain4j / 直接 API 三选一 | 待实验 |
| Search | 项目自有 `SearchProvider` + 一种实际供应商 | 供应商待定 |
| 进度 | 优先评估 SSE；保留轮询降级 | 待实验 |
| 持久化 | 先判断是否需要任务历史；需要时优先 PostgreSQL | 待产品确认 |
| 输出 | 结构化报告模型 + Markdown 展示 | 方向已确认 |
| 测试 | 步骤级单测、Provider 契约测试、Workflow 集成测试、前端/E2E | 原则已确认 |

## 3. 计划结构

```text
React Web
   ↓ REST + optional SSE
Spring Boot
   ├── research-api
   ├── workflow-orchestrator
   ├── planner
   ├── search-provider
   ├── evidence
   ├── analyzer
   ├── report-writer
   └── evaluation
        ↓
LLM API / Search API / optional PostgreSQL
```

步骤间通过项目自有结构化对象传递数据，不直接传递供应商响应或未校验的模型文本。

## 4. 控制权规则

| 决策 | 控制方 |
|---|---|
| 是否依次执行 Plan、Search、Evidence、Analyze、Write | Java 程序 |
| 计划中生成哪些受限搜索主题 | LLM，受 Schema 与数量约束 |
| 是否超过搜索次数、时间或成本上限 | Java 程序 |
| 搜索结果来自哪里 | Search Provider |
| 哪些证据允许进入报告 | Java 规则 + 受控模型提取 |
| 报告文字如何组织 | LLM |
| 任务是否成功、部分成功或失败 | Java 状态机 |

## 5. 必须验证的技术风险

1. Java AI 库的结构化输出是否稳定、可校验和可测试；
2. 候选搜索服务的输入、结果字段、限流、费用和使用条款；
3. SSE 在本地和目标部署环境的连接、断线与刷新行为；
4. 网页正文是否由搜索供应商提供，是否需要额外抓取；
5. 引用如何稳定关联来源，而不是让模型自由生成编号；
6. 测试环境如何使用固定模型响应和搜索样本；
7. 单次研究任务的调用数、上下文大小和费用上限。

## 6. 暂不引入

- LangGraph 或持久化图执行引擎；
- 多 Agent；
- 向量数据库和长期 Memory；
- 消息队列；
- 自动网页抓取集群；
- 多搜索 Provider 自动路由；
- 模型自主无限搜索。
