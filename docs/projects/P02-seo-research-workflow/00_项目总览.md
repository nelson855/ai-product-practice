# P02：SEO Research Workflow 项目总览

## 1. 核心结论

P02 将 DAIR.AI Deep Research Agent 中的研究流程转化为一个 Java 实现的 SEO 研究产品。主流程由程序固定，LLM 只负责计划内容、证据提取和报告生成，不拥有任意改变流程的权力。

参考项目是 [DAIR.AI Deep Research Agent](https://github.com/dair-ai/deep-research-agent)。自己的实现采用 React + Java/Spring Boot，目标不是复刻通用 Deep Research，而是完成面向关键词和建站机会的垂直 Workflow。

## 2. 核心学习问题

```text
程序决定“下一步一定做什么”
LLM 决定“当前步骤具体输出什么”
```

本项目重点理解：

- Planner 应输出什么结构；
- Search API 与 LLM 的事实职责如何分离；
- Evidence 如何追溯到来源；
- Citation 如何与最终报告对应；
- 长任务如何反馈阶段进度；
- 固定 Workflow 为什么通常比自由 Agent 更稳定、更便宜、更容易解释。

## 3. V1 用户流程

```text
输入关键词或产品方向
→ 生成结构化研究计划
→ 执行有限次数的网页搜索
→ 提取并整理证据
→ 分析搜索意图与竞争情况
→ 生成带来源引用的建站建议报告
```

## 4. V1 范围

### 必须包含

- 单一研究任务输入；
- 结构化计划；
- 至少一种搜索 Provider；
- 来源标题、URL、摘要和证据记录；
- 固定 Workflow 编排；
- 阶段进度；
- Markdown 或结构化报告；
- 引用可追溯；
- 失败、超时和部分结果表达；
- 基础质量评估。

### 暂不包含

- 自由 Agent Loop；
- 模型任意选择下一阶段；
- 多 Agent 协作；
- 通用网页爬虫平台；
- 无界搜索；
- 向量数据库和长期 Memory；
- 付费订阅和完整用户体系；
- 自动发布 SEO 站点或内容。

## 6. 阶段

| 阶段 | 名称 | 主要结果 |
|---|---|---|
| P02-S01 | 参考 Workflow 运行与实验 | Pipeline 行为、输入输出和进度体验 |

## 7. 成功标准

1. 同一输入可以稳定经过固定阶段并生成可追溯报告；
2. 每项事实性结论能够关联搜索证据或明确标为模型分析；
3. 搜索次数、模型调用次数、超时和任务时长有上限；
4. 某一来源失败时不会生成伪造成功；
5. 用户能看到当前阶段和可理解的错误；
6. 固定 Workflow、部分模型路由和 Agent Loop 的差异有实验数据；
7. 能解释为何正式 V1 选择固定 Workflow。
