# P02：阶段与子需求拆分

## 1. 核心结论

P02 先确认参考项目真实 Pipeline，再围绕“控制权属于程序还是模型”拆解。正式版本只实现确定性 Workflow；部分路由和 Agent Loop 作为后期对照实验，不反向污染主架构。

## 2. 已冻结决策

| 编号 | 决策 | 实现含义 |
|---|---|---|
| P02-D01 | 前端 React + TypeScript，后端 Java + Spring Boot | 不沿用参考项目 JavaScript/Agent SDK 架构 |
| P02-D02 | V1 使用固定 Workflow | 阶段顺序由 Java 代码控制 |
| P02-D03 | Search 是事实入口 | LLM 不能凭内部知识伪造搜索证据 |
| P02-D04 | 研究范围有硬上限 | 查询数、来源数、耗时和模型调用必须受控 |
| P02-D05 | 引用必须可追溯 | 报告引用关联实际来源记录 |
| P02-D06 | A/B/C 只做对比实验 | Agent Loop 不作为 V1 默认实现 |

## 4. 依赖关系

```text
S01 真实运行
 ↓
S02 控制权和源码拆解
 ↓
S03 产品与技术方案
 ↓
S04 后端确定性 Workflow
 ↓
S05 前端与质量闭环

```

S04 完成前不得开始 A/B/C 对比，避免实验性 Agent 抽象影响固定 Workflow 基线。S05 的 Eval 数据集可以在 S03 后提前设计，但指标必须在主链稳定后冻结。

## 5. 端到端主链

1. 用户提交关键词和可选约束；
2. Planner 返回通过 Schema 校验的研究计划；
3. 程序按计划执行受控搜索；
4. 搜索结果被归一化、去重并提取证据；
5. Analyzer 形成搜索意图和竞争分析；
6. Writer 只基于允许的输入生成报告；
7. 引用关联到实际来源；
8. 用户看到进度、报告、限制和部分失败说明。

失败链至少覆盖：计划格式错误、零搜索结果、搜索超时、来源冲突、网页不可读、模型超时、引用缺失、任务取消和会话刷新。

## 6. 详细文档生成规则

- S01 已建立完整执行文档；
- S02 根据参考项目真实代码和实验结果编写；
- S03 必须与用户讨论模型、搜索 Provider、持久化和前端形态；
- S04～S06 只在 Workflow 状态与契约冻结后展开；
- 三种控制方式的对比实验不得先于确定性基线。

## 7. P02 完成定义

- 18 个子需求完成或有用户接受的明确阻塞；
- 正常与关键失败流程可重复验证；
- 报告事实、模型分析和引用边界明确；
- 固定 Workflow 的成本、调用数和延迟可测量；
- A/B/C 对比使用同一测试集和一致指标；
- 完成部署验证、文档同步和 Git 状态报告。
