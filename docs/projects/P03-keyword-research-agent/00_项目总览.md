# P03：Keyword Research Agent 项目总览

## 1. 核心结论

P03 是第一个真正允许模型决定“下一步做什么”的项目。目标是使用 Java 显式实现一个受控的关键词研究 Agent，通过 Tool、Loop、State、停止条件、Tracing 和 Eval 理解 Agent 自主性的价值与代价。

主要参考 [LangChain RAG Research Agent Template](https://github.com/langchain-ai/rag-research-agent-template) 的 Graph、State、Routing 和 Subgraph 思路；使用 [darshil0/deep-research-agent](https://github.com/darshil0/deep-research-agent) 补充观察产品化、搜索回退和错误恢复。参考项目的框架实现不是正式项目必须复制的结构。

## 2. 与 P02 的本质区别

P02：

```text
Plan → Search → Evidence → Write
顺序由 Java 固定
```

P03：

```text
读取目标与当前 State
→ 选择 Tool 或 Final
→ 执行并更新 State
→ 判断证据是否足够
→ 必要时继续循环
```

模型可以选择下一项受限动作，但不能突破工具权限、步骤数、搜索次数、成本和时间限制。

## 3. V1 用户流程

```text
输入关键词和研究目标
→ Agent 判断需要哪些信息
→ 调用搜索或证据工具
→ 更新研究 State
→ 判断信息是否足够
→ 必要时调整查询继续搜索
→ 生成带来源的关键词机会报告
```

## 4. V1 范围

### 必须包含

- 明确的 Agent Goal；
- 至少两个有清晰 Schema 的 Tool；
- 模型驱动的下一动作选择；
- 显式、可检查的 Agent State；
- 有上限的 Agent Loop；
- 最大步骤、搜索调用、耗时和成本边界；
- Tool 超时、错误和无结果处理；
- 简短决策摘要，不记录隐藏思维链；
- Tracing 与评估数据；
- 最终报告和来源引用；
- 与确定性 Workflow 基线对比。

### 暂不包含

- Multi-Agent；
- 无限制浏览和代码执行；
- 通用 Tool 插件市场；
- 长期个人 Memory；
- 自动建站、购买域名或发布内容；
- 持久化 Checkpoint 和跨天恢复，除非实验证明确有必要；
- Python/LangGraph 正式实现。

## 7. 成功标准

1. Agent 只能调用允许的 Tool，并经过输入校验；
2. 每次运行都在硬限制内结束；
3. Tool 失败、空结果和冲突证据不会导致无限循环；
4. 决策日志说明动作和简短原因，但不暴露隐藏思维链；
5. 最终报告中的事实能够追溯到 Tool 结果；
6. 固定测试集可以测量成功率、Tool 选择、调用数、成本和延迟；
7. 与 P02 风格的确定性基线相比，能说明自主性在哪些问题上带来真实收益；
8. 能基于实际问题判断是否需要 LangGraph、Checkpoint 或 Multi-Agent。
