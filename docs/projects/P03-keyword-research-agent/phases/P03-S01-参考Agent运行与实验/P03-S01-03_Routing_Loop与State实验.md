## 3. 实验范围

至少选择两类，并优先覆盖三类机制中的两类：

- Routing：改变一个可控输入或路由条件，观察 Edge 选择；
- Loop：降低步骤或计划上限，观察终止和未完成状态；
- State：为关键更新添加安全日志或断言，观察字段如何累积；
- Retrieval：改变查询数或并行度，观察结果合并；
- Failure：让一个 Tool/检索步骤失败，观察重试、降级或终止；
- Replay：若原项目支持，验证从已有 State 调试或重放的实际边界。

## 4. 必须记录

- 实验问题与假设；
- 修改文件和最小差异；
- 输入、动作序列、关键 State 前后值和结束原因；
- 调用数、耗时和错误；
- 证据等级；
- 对 Java Agent 设计可复用的机制，而不是框架 API 名称。

## 5. 边界

- 不大规模升级归档项目；
- 不输出完整模型推理过程，只记录动作和简短决策摘要；
- 不开放任意 Tool 或系统权限；
- 不提交、推送或部署；
- 不开始正式 Java 实现。

## 6. 验收标准

- 至少两项实验可重复；
- 至少覆盖 Routing、Loop、State 中的两类；
- 每项结论区分运行证据与源码推断；

- 实验差异不含 Secret、生成物和无关重写；
- 已形成 Java 技术实验需要验证的问题清单。
