# P03：阶段与子需求拆分

## 1. 核心结论

P03 不从 Agent Loop 直接开始。先建立受控 Tool 和确定性基线，再加入模型驱动的动作选择；否则无法判断复杂度来自业务问题还是 Agent 框架。

## 2. 已冻结决策

| 编号 | 决策 | 实现含义 |
|---|---|---|
| P03-D01 | 正式实现采用 Java + Spring Boot | Python/LangGraph 只作为参考，不是首版依赖 |
| P03-D02 | 先实现确定性基线 | Agent 必须与同任务基线对比 |
| P03-D03 | Tool 采用显式输入输出 Schema | 不允许把任意函数和系统能力暴露给模型 |
| P03-D04 | Agent 自主性有硬限制 | 步骤、搜索、成本、时间和上下文均受控 |
| P03-D05 | 记录简短决策摘要 | 不请求或保存隐藏 Chain-of-Thought |
| P03-D06 | Eval 是功能的一部分 | 不只凭个别漂亮结果判断 Agent 质量 |
| P03-D07 | 不默认需要持久化 Graph | 只有真实恢复需求成立后才评估 LangGraph 类能力 |

## 5. Agent 决策与停止规则

实现阶段至少需要以下动作类别，实际名称在 S03 冻结：

```text
search
inspect_evidence
revise_query
final
```

Agent 必须在以下任一条件发生时停止或降级：

- 达到最大步骤；
- 达到最大搜索调用；
- 达到时间或成本预算；
- 连续重复相同动作或查询；
- Tool 连续失败；
- 模型返回非法动作且修复次数耗尽；
- 已满足正式结束条件。

## 6. 端到端主链与失败链

主链：目标输入 → 状态初始化 → 动作选择 → Tool 执行 → 状态更新 → 继续或 Final → 报告与引用。

失败链至少覆盖：非法 Tool 输入、未知 Tool、搜索无结果、Tool 超时、重复动作、证据冲突、模型输出无法解析、达到预算、用户取消和报告引用缺失。

## 7. 详细文档生成规则

- S01 详细文档已经建立；
- S02 基于主参考与补充参考的真实结构编写；
- S03 必须先讨论 Java AI 库、模型、Search、状态持久化和部署；
- S04 先于 S05 展开；
- S07 的 LangGraph 判断只能使用本项目实际遇到的问题，不能因为参考项目使用 Graph 就预设结论。
