# P03：技术栈设计

## 1. 当前结论

P03 采用 React + TypeScript 与 Java + Spring Boot。Agent Runtime 先用项目自有 Java 类型显式表示动作、工具、状态、预算和循环；AI 库只负责模型调用与结构化动作生成，不让框架隐藏核心机制。

## 2. 当前选型

| 领域 | 当前选择 | 状态 |
|---|---|---|
| 前端 | React + TypeScript，优先 Vite | 方向已确认 |
| 后端 | Java + Spring Boot | 已确认 |
| Agent 编排 | 显式 Java Loop + State | 已确认 |
| AI 集成 | Spring AI / LangChain4j / 直接 API | 待实验 |
| Tool Runtime | 项目自有接口、Schema、超时和结果类型 | 方向已确认 |
| Search | 受控 `WebSearchTool`，供应商待定 | 待实验 |
| 持久化 | 先以内存单任务 State 验证；历史是否落 PostgreSQL 待定 | 待确认 |
| 进度 | SSE 或轮询 | 待实验 |
| Eval | 固定 JSON/Markdown 用例 + 自动指标 + 人工评分项 | 方向已确认 |
| Tracing | 项目自有结构化 Step Event，必要时再接外部平台 | 方向已确认 |

## 3. 核心类型草案

```text
AgentGoal
AgentState
AgentAction
ToolDefinition
ToolInput
ToolResult
Evidence
AgentBudget
AgentStepEvent
FinalReport
```

这些是设计职责，不代表最终类名。S03 技术实验后再冻结公开接口。

## 4. 运行结构

```text
while stopCondition 未满足:
    基于 Goal + State 生成结构化 AgentAction
    校验 Tool、输入和权限
    执行 Tool（超时、限流、错误映射）
    将可保留结果写入 State
    记录 Step Event 和预算消耗

生成 Final 或受控失败结果
```

模型不能直接执行系统命令、访问任意网络地址、读取本地文件或绕过 Tool Runtime。

## 5. Tool 设计要求

每个 Tool 必须定义：

- 稳定名称和用途描述；
- 输入 Schema 与业务校验；
- 输出 Schema 与大小上限；
- 权限和允许访问的资源；
- 超时、重试和限流；
- 错误类型；
- 幂等性和副作用；
- 日志脱敏规则；
- 测试替身和固定样本。

V1 优先只提供只读 Tool，避免模型触发外部写操作。

## 6. State 与上下文原则

- State 保存任务事实、证据、动作结果、预算和结束原因；
- 不保存隐藏思维链；
- 对重复证据、超长正文和无关历史进行裁剪；
- 模型上下文是 State 的受控投影，不等同于完整持久化状态；
- 每次状态更新必须能够解释来源；
- 是否持久化 Checkpoint 由实际恢复需求决定。

## 7. 必须完成的技术实验

1. Java 模型调用生成符合 Schema 的动作；
2. 非法动作能够校验、有限修复并稳定失败；
3. 至少两个 Tool 可以注册、调用、超时和使用测试替身；
4. Loop 能在步骤上限、重复动作和 Tool 连续失败时终止；
5. Step Event 可以驱动前端进度而不暴露敏感 Prompt；
6. 同一固定输入可以收集调用数、Token、延迟和最终状态；
7. 不依赖 LangGraph 也能完整观察核心 Agent 机制。

## 8. 暂不引入

- Python/LangGraph 正式后端；
- Multi-Agent 和 Agent-to-Agent 通信；
- 任意代码执行或通用浏览器控制；
- 长期向量 Memory；
- 默认持久化 Checkpoint；
- 自动 Replan 子图和复杂并行 Graph；
- 外部 Tracing SaaS 强绑定。
