# P01：技术栈设计

## 1. 当前结论

P01 采用前后端分离的 React + Java/Spring Boot 单体方案。当前只冻结技术方向；认证细节、图片供应商和目标部署平台需在参考项目分析及技术实验后确认。

| 前端 | React + TypeScript | 已确认 |

## 3. 计划模块

```text
React Web
   ↓ HTTPS/JSON
Spring Boot Application
   ├── identity        用户与授权
   ├── media           上传文件与对象存储
   ├── generation      图片生成用例与状态
   ├── provider        模型供应商适配
   └── observability   错误、日志与指标
        ↓
PostgreSQL / S3-compatible storage / Image model API
```

模块名称只是当前边界草案，最终包结构由 S03 的架构设计确定。

## 4. 关键设计原则

- 浏览器不能直接持有模型和对象存储管理凭证；
- 业务状态以项目数据库为权威，存储对象只保存文件内容；
- 图片供应商响应不能直接成为公开 API；
- 生成状态必须区分等待、处理中、成功和失败；
- 数据库记录与对象存储操作无法形成单一事务时，要设计补偿或可恢复状态；
- 用户访问文件必须经过授权或使用短时签名 URL；
- V1 不为了未来扩展提前拆微服务或引入消息队列。

## 5. S03 必须完成的技术实验

1. Java 调用候选图片模型并保存一张结果；
2. Spring Boot 通过 S3 兼容接口完成上传、读取和删除；
3. 验证本地 MinIO 与目标线上存储的兼容边界；
4. 验证候选认证方式在 React 前后端分离部署下的 Cookie、CORS 和 CSRF 行为；
5. 测量一次生成的延迟、响应形态和失败类型；
6. 验证测试环境可以替换模型和存储 Provider，不依赖真实付费调用。

## 6. 暂不引入

- Python 后端：当前能力 Java 可以合理完成；
- LangChain/LangGraph：图片生成不需要 Agent 抽象；
- Kafka/RabbitMQ：只有生成吞吐和可靠异步需求经实测成立后再评估；
- Redis：没有共享缓存、限流或任务协调证据前不引入；
- 向量数据库：本项目没有检索需求；
- Stripe：V1 先验证完整使用链和真实成本。
