# P01：AI Image Mini SaaS 项目总览

## 1. 核心结论

P01 的目标不是学习 Agent，而是把“根据 Prompt 生成图片”这一项 AI Feature 包装成可注册、可使用、可追踪、可部署的 Mini SaaS。

参考项目是 [Backblaze AI SaaS Starter Kit](https://github.com/backblaze-labs/ai-saas-starter-kit)。自己的实现使用 React + Java/Spring Boot，从空目录重写，不延续参考项目的 Next.js + FastAPI 实现。

## 2. 学习目标

重点学习：

- AI Provider 如何被限制在清晰边界内；
- 用户、权限、文件、生成记录和对象存储如何形成完整主链；
- 模型失败、存储失败和数据写入失败如何一致处理；
- 一个简单 AI 能力上线时还需要哪些产品工程；
- 成本、限流、日志和部署如何影响产品设计。

本项目不学习 Agent Loop、Memory、Planning、Multi-Agent 或 LangGraph。

## 3. V1 用户流程

```text
注册或登录
→ 输入 Prompt，可选上传参考图片
→ 发起一次图片生成
→ 查看生成状态和错误
→ 查看生成结果
→ 在历史记录中再次查看
```

## 4. V1 范围

### 必须包含

- 最小用户认证；
- 图片上传；
- 一种图片生成能力；
- 生成记录与状态；
- 生成图片保存；
- 历史记录；
- 基本错误处理、限流和可观察日志；
- 本地可重复运行；
- 一种可验证的部署方案。

### 暂不包含

- Team 和组织管理；
- 完整订阅、支付与 Billing Portal；
- 复杂 Admin Console；
- 多模型自由切换；
- 社区、模板市场或公开作品广场；
- 复杂图片编辑器；
- Agent 能力。

积分或配额只在模型成本已经可以真实测量后决定是否加入，不提前实现完整计费系统。

## 6. 阶段

| 阶段 | 名称 | 主要结果 |
|---|---|---|
| P01-S01 | 参考项目运行与实验 | 可重复运行记录、核心流程体验、实验差异 |
| P01-S02 | 源码与产品架构拆解 | 图片生成调用链、SaaS 基础设施和成本分析 |
| P01-S03 | Mini 产品与技术方案 | V1 产品规格、技术实验、架构与契约 |
| P01-S04 | 基础工程与用户文件能力 | 工程骨架、认证、上传和对象存储主链 |
| P01-S05 | AI 图片生成主链 | Provider、生成状态、历史和前端闭环 |
| P01-S06 | 上线验证与对比复盘 | 可靠性、部署、对比和学习总结 |

完整子需求见 [01_阶段与子需求拆分.md](01_阶段与子需求拆分.md)。

## 7. 项目成功标准

1. 新用户能够完成登录、生成图片并从历史记录再次查看；
2. 用户只能访问自己的上传文件和生成记录；
3. 模型、数据库或对象存储失败时有明确状态，不产生伪成功；
4. 模型供应商和存储供应商通过项目接口隔离；
5. 至少一条主链和关键失败链可以自动化验证；
6. 能说明参考项目中保留、删除和重做的设计及原因；
7. 能估算单次生成和典型使用量的模型与存储成本；
8. 项目可以在文档描述的环境中重复启动和部署验证。
