# P01：阶段与子需求拆分

## 1. 核心结论

P01 先研究一个成熟 AI SaaS 如何组织产品能力，再从零实现最小图片产品。正式开发前必须完成产品范围和技术方案冻结，避免把参考项目的全部基础设施照搬进练习项目。

## 2. 阶段交付与非目标

| 阶段 | 交付重点 | 本阶段不做 |
|---|---|---|
| S01 | 跑通参考项目并完成可回退实验 | 不设计自己的正式代码 |
| S02 | 形成调用链、模块和产品工程分析 | 不复制参考项目源码 |
| S03 | 冻结 V1、技术栈和架构契约 | 不开始全量功能开发 |
| S04 | 建立用户与文件纵向主链 | 不接完整图片生成产品流程 |
| S05 | 完成图片生成和历史闭环 | 不增加 Billing、Team 等扩展能力 |
| S06 | 完成可靠性、部署和复盘 | 不自动发布到生产环境 |

## 3. 已冻结决策

| 编号 | 决策 | 实现含义 |
|---|---|---|
| P01-D01 | 自实现后端采用 Java + Spring Boot | 不沿用参考项目 FastAPI 后端 |
| P01-D02 | 前端采用 React + TypeScript | Vite 或 Next.js 在 S03 冻结 |
| P01-D03 | V1 只接一种图片生成能力 | Provider 接口可扩展，但不先做多模型 UI |
| P01-D04 | 参考项目允许注释和小改动 | 实验差异必须可追溯，不直接成为正式实现 |
| P01-D05 | 先做完整主链，再考虑计费 | 没有真实成本证据前不建设 Billing |
| P01-D06 | 正式项目从空目录实现 | 不通过 Fork 后持续魔改完成 P01 |

## 5. 依赖关系

```text
S01 基线与运行
  ↓
S02 架构拆解
  ↓
S03 产品与技术方案
  ↓
S04 用户和文件基础
  ↓
S05 图片生成闭环
  ↓
S06 上线验证与复盘
```

S02 的三个子需求可以在 S01 完成后并行分析，但调用链拆解应先提供核心模块索引。S04 中工程骨架先于认证和存储；认证与存储可在契约冻结后并行。S05 必须复用 S04 的用户隔离和文件边界。

## 6. 详细文档生成规则

- S01 的详细文档已经建立，可立即执行；
- S02 详细文档在 S01 产出真实仓库结构、运行结果和实验差异后编写；
- S03 在 S02 结论基础上与用户讨论并冻结；
- S04～S06 只在前置架构和契约确定后展开为实施文档；
- 新文档不得把未验证的参考项目行为写成事实。

## 7. 端到端验收主链

1. 用户注册或登录；
2. 用户上传可选参考图片并输入 Prompt；
3. 后端校验身份、输入和使用限制；
4. 图片 Provider 返回成功结果或稳定错误；
5. 成功结果进入对象存储并写入生成记录；
6. 前端展示结果；
7. 用户在历史记录中重新查看；
8. 其他用户无法访问该文件和记录。

失败链至少覆盖：非法文件、模型超时、模型拒绝、存储失败、数据库失败、会话过期、越权读取和重复请求。

## 8. P01 完成定义

- 18 个子需求达到各自验收标准；
- 主链和关键失败链有可重复验证证据；
- 技术设计与实际实现一致；
- 成本、数据和用户隔离边界明确；
- 参考项目实验改动与正式实现清晰分离；
- 完成部署验证、架构对比和学习复盘；
- 报告 Git 状态，未经要求不提交、推送或发布。
