# P01-S01-03：注释与小改动实验

## 1. 核心结论

通过少量注释、日志或行为修改验证对参考项目关键机制的理解。实验以产生明确结论为目标，不限制 `references/` 为只读，也不进行大规模重构。

## 2. 状态

| 属性 | 内容 |
|---|---|
| 状态 | 未开始 |
| 必需前置 | P01-S01-02 已完成或关键流程已明确受阻 |
| 主要交付物 | `progress/p01/reference_experiments.md` 与参考仓库未提交差异 |

## 3. 实验选择

根据实际运行结果选择至少两项，优先从以下方向选择：

- 在图片生成主链添加安全的阶段日志，观察模型、数据库和存储顺序；
- 修改一个非敏感 Prompt 或生成参数，比较请求与结果变化；
- 为关键 Service 或 Provider 添加解释性注释；
- 人为触发模型失败或存储失败，观察状态和用户提示；
- 小范围调整套餐或权限判断，观察能力边界；
- 增加一个针对核心流程的最小测试。

实验选项必须与实际仓库结构匹配，不能为了满足数量编造不存在的机制。

## 4. 实现范围

- 为每项实验写明问题、假设、最小改动、输入和预期；
- 修改前记录相关文件和基线行为；
- 执行实验并保存非敏感结果；
- 比较前后行为，判断假设是否成立；
- 使用 `git diff` 汇总修改；
- 提炼对自己 Java 实现有价值的结论。

## 5. 边界

- 不进行框架迁移、大规模重构或依赖升级；
- 不删除原功能或清理他人文件；
- 不输出隐藏思维链，只记录可观察行为和简短判断依据；
- 不提交或推送实验改动；
- 不将参考项目改造成正式 P01 项目。

## 6. 验收标准

- 至少两项实验具有明确问题、改动、结果和结论；
- 注释解释设计意图或调用关系，而不是逐行翻译；
- 实验可通过命令和输入重复；
- `git diff` 中没有密钥、生成物或无关格式化；
- 明确列出哪些观察值得带入自己的设计，哪些只属于上游技术栈。

## 7. Coding Agent 执行要求

只执行已选择的实验。完成测试和结果记录后保留未提交改动，报告 `git diff --stat`、关键差异、测试结果和 `git status`，然后停止。不得自动还原、提交、推送或进入 S02。
