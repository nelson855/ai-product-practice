# P01-S01-02：跑通核心用户流程

## 1. 核心结论

在基线版本上尽可能跑通“认证—上传—生成—历史”用户流程，并如实记录实际可用部分。外部账户或付费模型缺失时，可以分段验收，但不能用伪造成功替代真实阻塞。

## 2. 状态

| 属性 | 内容 |
|---|---|
| 状态 | 未开始 |
| 必需前置 | P01-S01-01 已完成 |
| 主要交付物 | `progress/p01/upstream_run_report.md` |

## 3. 实现范围

- 按上游说明安装依赖并启动必要组件；
- 记录启动命令、端口、耗时和问题处理；
- 验证健康检查、首页和基础导航；
- 在条件允许时依次验证注册/登录、文件上传、一次图片生成和历史查看；
- 记录每一步涉及的网络请求、数据变化和外部服务；
- 记录用户可见加载、成功、空状态和失败体验；
- 执行上游已有的相关测试或最小健康验证。

## 4. 边界

- 为适配本机环境可以修改未跟踪的本地配置，但不修改业务逻辑；
- 不使用生产密钥或真实敏感数据；
- 不为了“全部通过”绕过认证、套餐或权限检查；
- 不自动部署；
- 不提前做源码架构结论，只记录观察和待验证问题。

## 5. 交付物

运行报告至少包括：

- 实际成功运行的组件和用户流程；
- 未运行部分及具体阻塞；
- 页面与 API 的关键入口；
- 外部服务调用清单；
- 数据库和对象存储中可观察的变化；
- 典型成功与失败耗时；
- 用户体验问题；
- 下一步应深入追踪的调用链。

## 6. 验收标准

- 至少健康检查和一个用户可感知流程可以重复执行；
- 每个计划流程都有“成功、受阻或不适用”的明确结果；
- 报告不包含真实 Secret 和隐私数据；
- 所有临时适配改动均已列出；
- 运行结论来自实际结果，不来自 README 推测。

## 7. Coding Agent 执行要求

只执行本需求。需要付费账户、API Key 或改变外部系统状态时先停止并请用户决定。完成后报告测试、运行结果、工作区差异和 `git status`，不自动进入实验阶段。
