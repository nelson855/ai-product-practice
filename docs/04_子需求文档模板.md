# 子需求文档模板

> 本文件定义结构，不代表所有章节都必须写成长篇。内容以能够独立实施和验收为准。

# `<子需求编号>`：`<名称>`

## 1. 核心结论

用一段话说明本需求解决什么问题、交付什么结果，以及最重要的实现边界。

## 2. 状态

| 属性 | 内容 |
|---|---|
| 状态 | 未开始 / 进行中 / 已完成 / 受阻 |
| 所属项目 | P01 / P02 / P03 / P04 |
| 所属阶段 | 阶段编号和名称 |
| 必需前置 | 子需求编号或外部条件 |
| 主要交付物 | 文件、功能、报告或实验记录 |

## 3. 目标

- 用户、学习者或后续实现能够获得什么；
- 本需求完成后消除哪个不确定性；
- 为什么必须在当前阶段完成。

## 4. 输入和已知事实

- 需要阅读的文档；
- 前置需求的真实产物；
- 已确认技术或产品决策；
- 不得自行假设的未知项。

## 5. 实现范围

- 具体工作项；
- 需要创建或修改的功能与文档；
- 需要运行的实验或用户流程；
- 必须保存的结果证据。

## 6. 边界

- 明确不做什么；
- 不允许提前进入哪些后续工作；
- 不允许引入哪些额外技术；
- 对参考项目、正式项目和外部服务的修改限制。

## 7. 技术与执行要求

- 核心流程、接口或实验方法；
- 错误和边界条件；
- 数据、Secret 和隐私处理；
- 需要遵守的项目技术栈约束。

## 8. 交付物

列出可以检查的实际文件、功能、截图、日志摘要、测试或报告。避免使用“完成相关工作”之类无法核验的描述。

## 9. 验收标准

- 使用可观察结果描述；
- 正常流程与关键失败流程均有要求；
- 无法验证的外部条件明确标记；
- 文档结论可以追溯到代码、运行结果或权威资料。

## 10. 验证方式

列出自动化测试、构建、Lint、人工操作或对比方法。记录命令时使用项目约定环境，不写入真实密钥。

## 11. Coding Agent 执行要求

1. 只执行本子需求；
2. 开始前检查前置条件与 Git 状态；
3. 发现设计冲突先报告，不自行扩大范围；
4. 完成适用验证并记录结果；
5. 更新状态和必要文档；
6. 报告改动、测试、限制和 `git status`；
7. 不提交、不推送、不发布，完成后停止。

## 12. 完成记录

实施时填写：

- 完成日期；
- 实际交付物；
- 验证结果；
- 与原计划的差异；
- 遗留问题；
- 下一子需求进入条件。
