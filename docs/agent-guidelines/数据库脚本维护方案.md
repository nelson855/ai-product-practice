# 数据库脚本维护方案

## 1. 适用方式

本方案用于采用人工执行数据库脚本、且不依赖自动迁移工具的项目。项目已经稳定使用 Flyway、Liquibase 或其他迁移机制时，应依据现有事实调整本方案，不得机械替换。

默认维护方式为：

- 一份当前完整 Schema，用于空库初始化和结构总览；
- 按需求创建的增量变更 SQL，用于已有数据库升级和历史追溯；
- 测试数据与生产结构、生产变更脚本分离；
- 不设置 `pending` 状态目录，不要求程序记录数据库执行版本。

## 2. 目录结构

根据项目实际 SQL 根目录落地以下结构：

```text
<sql-root>/
├── schema-current.sql
├── changes/
│   └── YYYY-MM-DD-NN-<需求编号>-<变更说明>.sql
├── test/
│   └── seed.sql
└── archive/
```

- `schema-current.sql`：当前代码版本所需的完整数据库结构。
- `changes/`：按需求保存已有数据库需要执行的增量变更。
- `test/`：测试样例数据和辅助脚本，不得作为生产初始化步骤。
- `archive/`：退出当前维护范围的历史脚本，只用于追溯。

## 3. 变更脚本命名

需求确认包含数据库变更时，立即按以下格式创建脚本：

```text
YYYY-MM-DD-NN-<需求编号>-<kebab-case说明>.sql
```

规则如下：

- 日期使用需求或变更记录的创建日期，不使用生产发布日期；
- `NN` 是当天两位十进制顺序号，可沿用对应变更记录的序号；
- 文件创建后不因测试轮次、执行环境或发布日期变化而改名；
- 一个需求默认只创建一个变更 SQL，只有目标数据库、权限或执行边界确实不同才拆分；
- 文件名用于追溯来源，不负责自动判断执行顺序；跨需求依赖必须写入脚本头部和发布说明。

## 4. 当前完整 Schema

`schema-current.sql` 必须包含当前代码所需的全部表、字段、约束和索引，用于：

- 删除数据库后的重建；
- 新环境首次初始化；
- 查看当前完整结构；
- 核对增量升级后的最终结构。

该文件只面向空数据库执行，不兼容已有旧结构，不包含测试数据、生产业务数据修复或其他数据库的 DDL/DML。

## 5. 按需求变更 SQL

`changes/` 中的脚本只描述对应需求相对于其前置生产结构所需的变更。脚本头部至少写明需求编号、创建日期、变更目的、目标数据库、前置需求和执行注意事项。

同一需求在开发和测试期间反复调整时，直接修改已经创建的变更 SQL，并同步更新 `schema-current.sql`，不得因每次测试执行不断新增版本脚本。

变更 SQL 一旦在任一生产环境执行，即成为不可变历史：

- 不得修改、覆盖、删除或重命名；
- 发现遗漏或错误时，由后续需求创建新的变更 SQL；
- `schema-current.sql` 继续反映修正后的最终完整结构。

## 6. 阶段性整理

测试过程不属于生产数据库历史。正式发布前，应把同一需求的试错过程整理为一份从前置生产结构到目标结构的最终 SQL。

- 只整理尚未在生产执行的同一需求脚本；
- 不合并、重写或删除已经进入生产的历史脚本；
- 不把不同需求合成无法追溯来源的综合脚本；
- 整理由需求实现者完成，生产执行人员不负责现场合并 SQL。

## 7. 生产执行

### 7.1 新建或重建数据库

数据库为空，或者已经确认可以整体删除重建时，只执行当前发布包中的 `schema-current.sql`，不重放历史变更脚本。

### 7.2 已有数据库升级

保留现有数据和结构时，由 DBA 或运维通过项目已有的受控 SQL 渠道，人工执行本次发布涉及的需求变更脚本，并在现有发布单、需求单或运维记录中留痕。

执行前核对目标数据库和前置需求；不可逆或高风险变更必须先建立备份、恢复点或明确恢复方式。

## 8. 验证

包含数据库变更的需求至少验证两条路径：

```text
路径 A：空数据库执行 schema-current.sql
路径 B：前置生产结构执行本需求 changes SQL
```

两条路径完成后，相关表、字段、类型、默认值、约束和索引应一致。涉及数据转换时，还应验证代表性旧数据和失败后的恢复方式。

无法连接实际数据库时，应记录未执行的命令、原因和风险，不得只依据 SQL 文本声称已经可用。

## 9. 安全约束

- 明确目标数据库，避免误连后修改其他数据库。
- 增量脚本应让不符合预期的状态显式失败，不用大量存在性判断掩盖结构漂移。
- 删除表、删除列、收窄字段类型和不可逆数据更新必须单独标注风险。
- 测试种子数据不得依赖固定主键初始化生产。
- 通用回退脚本不是强制交付物；无法安全逆转的变更优先使用备份恢复或后续向前修复。
- SQL 与需求、完整 Schema 或接口契约冲突时，应先澄清并统一依据。
